# BXD Battle: бэкенд (FastAPI) + фронт

Что внутри
- `backend/` — сервер на FastAPI. Хранит блогеров, ролики и историю просмотров в БД (SQLAlchemy),
  считает рейтинг, сам запускает сбор через Apify.
- `frontend/index.html` — страница рейтинга. Сервер отдаёт её же, поэтому всё работает по одному адресу.
- `bloggers.csv` — список блогеров (`name,tiktok,instagram`).
- `Dockerfile` — запуск на хостинге.
- `.github/workflows/refresh.yml` — кнопка и расписание, которые просят сервер обновить рейтинг.

## API
| Метод и адрес | Что делает | Доступ |
|---|---|---|
| `GET /api/ranking` | рейтинг: блогеры по убыванию просмотров, итоги, время обновления | открытый |
| `GET /api/creators/{id}/videos` | засчитанные ролики блогера | открытый |
| `GET /api/status` | идёт ли сбор, итог последнего, когда можно следующий | открытый |
| `POST /api/refresh` | запускает сбор (платный, через Apify) | заголовок `X-Admin-Token` |
| `GET /health` | проверка, что сервер жив | открытый |

Защита от лишних трат: сбор нельзя запустить, если он уже идёт (ответ 409), и чаще, чем раз в
`MIN_REFRESH_HOURS` часов (ответ 429; `?force=true` обходит это ограничение). Без `ADMIN_TOKEN`
на сервере обновление отключено совсем.

Правила подсчёта те же, что в скрипте: ролик засчитывается, если хэштег указан в подписи целиком
(`#bxdbattle2` не подходит) и дата входит в период. Нет данных по платформе — это пометка и пустая
ячейка, а не ноль. Если обновление не удалось, остаются последние известные просмотры, рядом пометка.

## Настройки (переменные окружения)
| Переменная | Значение по умолчанию | Зачем |
|---|---|---|
| `APIFY_TOKEN` | нет | токен Apify (обязателен для сбора) |
| `ADMIN_TOKEN` | нет | длинный случайный пароль для `/api/refresh` |
| `DATABASE_URL` | `sqlite:///./bxd.db` | строка подключения к БД (на хостинге нужен внешний PostgreSQL) |
| `HASHTAG` | `BXDBATTLE` | хэштег без `#` |
| `PERIOD_START`, `PERIOD_END` | 2026-10-01, 2026-10-28 | период, включительно |
| `TZ_NAME` | `Asia/Almaty` | часовой пояс периода |
| `MAX_VIDEOS` | 10 | сколько последних роликов брать у аккаунта (влияет на расход) |
| `MIN_REFRESH_HOURS` | 6 | минимальный интервал между платными запусками |

## Запуск у себя
    cd backend
    python3 -m pip install -r requirements.txt
    export APIFY_TOKEN=ваш_токен_apify
    export ADMIN_TOKEN=придумайте_длинный_пароль
    uvicorn app.main:app --port 8000
Откройте http://localhost:8000 . Запустить сбор:
    curl -X POST http://localhost:8000/api/refresh -H "X-Admin-Token: придуманный_пароль"
Тесты: `python3 -m pip install pytest httpx` и `python3 -m pytest backend/tests`.

## Бесплатный хостинг
Нужны две вещи: место для сервера и внешняя база (на бесплатных хостингах диск сервера
не сохраняется между перезапусками, и данные в SQLite пропадут).
1. База: создайте бесплатный PostgreSQL (например, Neon или Supabase) и скопируйте строку
   подключения. Она пойдёт в `DATABASE_URL`.
2. Сервер: создайте на хостинге с бесплатным тарифом (например, Render) веб-сервис из вашего
   GitHub-репозитория, тип Docker (используется `Dockerfile`). В настройках добавьте переменные из таблицы выше.
3. Откройте адрес сервиса: страница должна загрузиться с сообщением «Данные ещё не собраны».
4. В репозитории: Settings → Secrets → Actions добавьте `SITE_URL` и `ADMIN_TOKEN`, затем вкладка
   Actions → «Обновить рейтинг на сайте» → Run workflow. Когда сбор закончится, рейтинг появится на странице.

Условия бесплатных тарифов у хостингов меняются (лимиты, сон при простое, срок жизни базы),
поэтому проверьте их на сайтах сервисов перед выбором. Бесплатный сервер «засыпает» без
посетителей и первый заход после паузы может грузиться около минуты.

## Расход Apify
Это тот же расход, что и у скрипта: ориентир: около $1 за 1000 полученных роликов (проверьте по своему первому запуску). Размер сбора задают
`MAX_VIDEOS` и частота запусков. Фактический расход последнего сбора виден в `GET /api/status`
(поле `cost_usd`).

## Что показывает страница мониторинга
- Весь список участников сразу, по убыванию просмотров; первые три места подсвечены.
- Стрелка «Сдвиг»: на сколько мест участник поднялся или опустился по сравнению с прошлым обновлением.
- Под числом просмотров: прирост за это же время.
- Вверху: сколько времени назад обновлены данные. Во время сбора страница проверяет сервер каждые 10 секунд,
  в обычное время каждые 30.
- Данные меняются в момент, когда завершается очередной сбор через Apify. Как часто он запускается,
  зависит от бюджета (см. раздел про расход).
